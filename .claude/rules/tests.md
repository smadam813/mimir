# Tests: the harness, and what a test has to prove

- `tests/Mimir.Server.Tests` mirrors the server's module folders: a test lands next to its subject (`Distillation/MergeGateTests.cs`), and a module's fakes live with them (`Distillation/FakeChatClient.cs`, `FakeDistiller.cs`, `FakeArbiter.cs`). The shared harness (`PostgresTestBase`, `ThrowawayDatabaseFixture`, `TestPostgres`, `DisconnectedContextFactory`) sits at the tests root.
- Postgres-backed test classes inherit `PostgresTestBase` (tests root) and write no plumbing: it owns the skip-gated `Context`/`Contexts`/`CreateContext`/`ConnectionString`, `Token`, `FromDb`, the fakes (`Embeddings`, `Arbiter`, `Chat`, `Clock`), the composed SUTs (`CreateMergeGate`, `CreateQueryRanking`), `AddThrowawayStorage` for a test booting its own DI graph, `Identity`/`Root` for the unique-per-call identity and root path a hand-seeded row needs, `RaceAsync` and the `WaitForABlockedSessionAsync`/`PollUntilAnyAsync` probes under it for a test whose winner has to stay uncommitted until the loser blocks, and the `AddProjectAsync` (both overloads — one mints an identity and root, one takes them)/`AddEpisodeAsync`/`AddEventAsync`/`AddWisdomAsync`/`AddHarvestedItemAsync`/`AddProvenanceAsync`/`AddHarvestProvenanceAsync`/`AddInjectionAsync`/`AddGoldenCaseAsync` seeders. It truncates every *mapped* table before each test, so a test may assert on whole-table counts and needs no prefix scoping, no queue parking and no hand-reset; the sibling-order failures that broke CI twice (#20, #22) are gone by construction (#73). Tables a test creates itself (`PostgresStorageProbeTests`' scratch tables) are outside that and live until the class's database is dropped — so no catalog-counting or only-table assertion can live in a class that makes them. Extend the harness rather than restating any of it in a class.
- Two things the harness asks of its callers, neither mechanically pinnable. The truncate reads the table list off the EF model, so a later entity is emptied the day it is mapped — but by the same token a second `HasData` seed, in any table, is truncated and *not* restored: adding one means extending `PostgresTestBase.ResetAsync`, which today restores the §3 Global row alone. And a class overriding `RecallOptions` for the service under test must hand the same instance to `CreateQueryRanking`, since the ranking reads the scoring knobs itself (`AffinityBoost`, `SalienceBoost`, `RecencyHalfLifeDays`); hand it the defaults and the test pins a value the ranked rows were never scored with (`PromptRecallServiceTests` is the worked example).
- A test class that creates files (`HarvestScannerTests`, `HarvesterServiceTests`) creates its temp root *after* `base.InitializeAsync()`, never before: the no-Postgres skip throws there, xUnit then runs no `DisposeAsync`, and a directory leaks per test per run.
- `GoldenSuiteTests` is the one Postgres-backed class that must *not* inherit `PostgresTestBase`: the §9 golden suite replays GoldenCases out of the development database, so an empty throwaway would leave it sweeping zero cases and passing forever. Its hand-plumbed `TestPostgres.AdminConnectionString` context is deliberate.
- A test that never issues SQL (argument checks, pure validation) must not inherit `PostgresTestBase`, because its skip-gated context would hide the guard on a machine with no Postgres. Build it over the shared `DisconnectedContextFactory` (or a plain never-connected `MimirDbContext`) so it runs, and fails, everywhere.
- bUnit renders components in two tiers, and neither is a third testing world — it is a renderer bolted onto the two above (#130). A component driven wholly by its parameters (`ConfirmDelete`) *inherits* `RenderTestBase`, which is `BunitContext` itself, so its pins run and fail on a Docker-less machine; a §8 surface injecting the `Ui/` browsers uses `PostgresTestBase.CreateRenderContext()`, which builds one over `AddThrowawayStorage`, the real `AddMimirUi`, `AddMimirHealth` for the snapshot the header reads, and `CaptureModule.AddServices` for the feed — every registration asked of the app's own composition rather than restated, since a harness that reinvents wiring can drift from it. A nullable cascade (`MainLayout.FirstRunCascade` carries `bool?`) cannot go through bUnit's `AddCascadingValue`, whose value is constrained `notnull`; put a real `CascadingValue<bool?>` in `RenderTree` instead. The "never inherit `PostgresTestBase` without issuing SQL" rule above picks the tier; no interface gets extracted over `WisdomBrowser` et al. to dodge it, since the concrete internal service is the seam (#66). The class's fakes come with it and have to: three of the four browsers take `TimeProvider` and `WisdomBrowser` takes `MergeGate`, so the render context registers `Clock` as the clock and `CreateMergeGate()` as the gate. Register `TimeProvider.System` there instead and the surface reads a different "now" from every other SUT the class composes.
- Two costs a render test on the Postgres tier pays, both worth knowing before the third one is written. A surface querying in `OnParametersSetAsync` paints its rows on a later render than the first, so wait for those with `WaitForAssertion` past bUnit's one-second default — what it does *before* its first await (claiming the search box) needs no wait, and is where a lifecycle pin belongs when it can go there. And the live surfaces debounce on **real** timers: `Debouncer` hard-codes 250 ms and deliberately has no `TimeProvider` seam, because what its own tests pin is that a superseded run is *cancelled*, and a fake clock would only pin that against itself — `Task.Delay` is what the production path waits on. So a claim that schedules a refresh costs a superseded query plus a real delay. That is why the wait above is seconds rather than milliseconds, and why the failure mode is an opaque timeout. It has a second failure mode that reads as nothing to do with timing: a test that finds an element and dispatches an event on it *afterwards* gets `UnknownEventHandlerIdException`, because the debounced refresh re-rendered in between and the handler id it captured belonged to the render before. Waiting longer does not fix that — waiting for **quiescence** does, so anything that clicks goes through `SettleAsync()` first and dispatches inside `InvokeAsync` — both in `tests/Mimir.Server.Tests/Components/RenderQuiescence.cs`, which the test project imports as a static using so every class calls them unqualified. That file is the whole of the hand-tuned wait, so when `Debouncer` gains a seam or a quiescence hook (#144) that body changes and no test does. What it measures is render *silence*, not the absence of work in flight — a query that has been issued renders nothing until it comes back — so a test asserting a query did **not** run passes `SettleAsync(Patience)` and waits the same bound a positive pin trusts a query to land inside; the default window would read the screen before the regression could reach it.
- `TestPostgres` is the one place the test-Postgres convention lives — the `MIMIR_TEST_POSTGRES` override, the compose default, the short timeouts that keep the no-database path fast, and the skip text. A second copy of any of it turns a config change into silent skips rather than failures. To see what a contributor without Docker sees, run with `MIMIR_TEST_POSTGRES="Host=127.0.0.1;Port=1;Username=nobody;Password=nobody;Database=nope"`: every Postgres-backed class skips and what still runs is their whole safety net. Mutation-check a pure guard under that, not just with Postgres up.
- Observing a lock wait: `pg_locks` rows for `transactionid` carry a NULL `database`, so a probe joining `pg_database` sees advisory waits only. A mutation check that drops a lock then times out instead of going red, because the racer blocks on the row conflict rather than the lock it no longer takes. Poll `pg_stat_activity` filtered to `datname = current_database()` and `wait_event IN ('advisory','transactionid')` (#70).
- A hand-built DI graph in a test must mirror `AddMimirStorage`: both `AddDbContextFactory<MimirDbContext>` and `AddDbContext<MimirDbContext>(..., optionsLifetime: ServiceLifetime.Singleton)`. Register only one and a service taking the other won't resolve; drop the singleton options and the factory poisons every singleton resolving from the root (#23).
- A test asserting on a raw string literal (`FirstRunCommandsTests`) asserts per line, never whole-string: the literal carries the checkout's line endings, CRLF on a Windows working copy and LF on CI's.
- A pure test that reads a shipped file directly (not through DI) needs it physically present in the test project's output. Mirror `AppSettingsTests`' `<Content Include="..." CopyToOutputDirectory="PreserveNewest" />` in the `.csproj` rather than reaching across the repo with relative paths; globs work (`wwwroot\**\*.css`) and `LinkBase` preserves subfolders (`OfflineAssetsTests`, #88).

## Mutation-checking a test

A test proves nothing until you break what it pins and watch it go red. The check itself comes out false in four ways.

- A test that pins a mechanism (a lock, a rollback, a cleanup) gets mutation-checked before review: remove the mechanism, confirm the test fails, restore. Restore from a copy of the file, because `git checkout -- <path>` reverts it to HEAD and takes the uncommitted work with it. Record each result in the commit message or PR body; reviewers ask for the red runs otherwise. Review rounds reject vacuous assertions (#61).
- A test that pins a structural property (filter-before-LIMIT, two methods over one clause) proves nothing until mutation-checked: apply the regression temporarily, confirm the test goes red, revert. Run each mutation against every entry point, because a predicate enforced redundantly elsewhere keeps one of them green (#67: the search legs' own `@include_retired` masked a broken ambient clause; only the queryless listing caught it). "Every entry point" means every site the guard could sit, not just every public method: `MergeGate.EditAsync` reads its row twice (unlocked pre-check, then again under the lock), so a guard mutation belongs at both (#71).
- A test over a threshold is only as good as its constants: they must straddle *only* the term under test. `budgetChars: 60` "proved" the Brief bought room for its tripwire line out of its own budget, when the 118-char wrapper alone already overran 60, so it stayed green under the mutation that stopped reserving the line at all. Pick a bound the rest fits inside and the term under test pushes past (#83).
- A hybrid-search fixture decides which leg it is testing, and says so nowhere: a query sharing no word with the seeded Wisdom ranks on the vector leg alone (`UserPromptEndpointTests`, `GoldenRunnerTests`). Change the wording at either end and the test goes on passing while pinning a different leg.
- A timing test that waits for something to *not* happen is safe on a slow box; one whose correctness needs a gap to stay *under* a delay is not. `DebouncerTests`' ceiling pair is the only one of that shape, which is why it runs on its own longer delay: its burst signals every 10 ms against a 100 ms delay, and a box that stretched that gap past the delay would let the trailing edge elapse mid-burst and break both tests. Windows' timer granularity already rounds 10 ms up to about 16 ms, so the nominal 10× margin is nearer 6× there.
- The fixture decides whether a mutation can go red at all: the right assertion at the right entry point still proves nothing if the setup leaves the regression with nothing to change. Two ways it hides, both from #77's review round. Rows seeded already in the order asserted make a dropped `ORDER BY` invisible, because the heap hands them back in insertion order and the list is right by accident, so seed them out of it (`AddEventAsync(seq: 2)` before `seq: 1`). And a test double that answers a default on an unscripted call makes every "how many times" claim unfalsifiable, so `FakeDistiller` throws the way `FakeChatClient` does and "answered with none" is an explicit `Enqueue()`. Before that, distilling once per Event instead of once per Episode left the whole suite green.
