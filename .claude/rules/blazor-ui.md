# Blazor UI: surfaces, chassis and stylesheets

bUnit renders components, but it is the placement ladder's *last* rung (#130). A rule about what is **computed** — wording, ordering, clamping, diffing, counting — still lives outside the `@code` block: a pure companion `.cs` (`ProjectRoute`, `ConfirmArming`, `FirstRunCommands`, `ModelPull`, each pinned under `tests/…/Components/`), or the data-shaping layer in `Ui/` (`WisdomBrowser`, `EpisodeBrowser`, `SurfaceSearch`, …) that `tests/Mimir.Server.Tests/Ui` reaches directly. A render test pins only what rendering alone reaches: that the markup calls the companion, which branch renders, lifecycle across a parameter change (`EpisodeListTests`), event dispatch (`ConfirmDeleteTests`), JSInterop through bUnit's stub. Nothing that already lives in a companion gets rewritten as a render test. CSS is out of bounds permanently — bUnit owns the DOM a component writes, the `SurfaceChassisTests`/`OfflineAssetsTests` scans own the stylesheet text, and the browser's rendering of either (the popover `display` trap below, scoped-bundle ordering, flex sizing) stays doc-only. The two tiers a render test picks between are in `.claude/rules/tests.md`.

Two chassis conventions the #86 surface ports each inherit (#91 set both, #94 extended them). The header's search box is claimed, not wired: a surface calls `SurfaceSearch.Claim(this, placeholder)`, disposes the token in `Dispose`, subscribes to the one `Changed` event (raised on claim, keystroke and release), and re-reads `Search.Term` off the service, so the box renders disabled with an explanation while nothing holds it. Two consequences follow, each of which has cost a bug. The claim is held by holder identity, so a re-claim by the same component makes any earlier token stale, and disposing that stale token later hands the box back out from under the live claim: release first, then re-claim. And the term is per claim, not per circuit, so a surface that stays mounted across a parameter change (Blazor reuses the instance where the route and component match) must release and re-claim, or it narrows the new Project by the old one's term (#94). All three ported surfaces shed it on that boundary now (#108); only the Episode list could reach the leak through a link, since every sidebar row points at the episodes route, so on the other two it was latent rather than absent. Where a surface claims in `OnInitialized` — Wisdom and Injections do — anchor the Project there too, since the parameters are already set by then and the boundary branch would otherwise re-claim over a claim one line old. `EpisodeList` claims from the boundary alone instead, because Global must hold no claim at all.

`MainLayout` decides how the body sits, from the URL: `BodyFit` gives a surface `.app-body.is-flush` (a flex column, scrolling delegated to the surface's own panes) and leaves everything else the plain scrolling body. A surface's root therefore mirrors `WisdomSurface`'s (`flex: 1; min-height: 0; display: flex`), with `min-height: 0` panes inside rather than `height: 100%`. The test is `ProjectRoute.Parse(...) is not null` — a `projects/{id}` URL always names one of the three, since `Parse` folds a missing or unrecognised tab onto Episodes, and drill-downs are routes on their surface's own page rather than a segment deeper (#95); `ProjectRoute.IsSurfaceRoot` and `IsPortedSurface`, which each told two cases apart while there were two, went with #95 and #97. The body itself draws no padding: the first-run panel wants its accent wash at the pane's edges (#90), a surface fills it, and the handful of routes that are neither wear `.page-notice` (#97). `UnknownProject` is the one `.page-notice` that renders *inside* a flush body — `BodyFit` reads the URL, not the page, so an id that resolves to nothing still lands in the surface body — which is why that class carries a padding and an overflow the other callers never exercise.

Two shapes are stated once and hosted everywhere, so a fix lands in one place. Every §8.2 hard delete — the Wisdom detail's, the whole Episode's, each Event's — is drawn by `ConfirmDelete`, never by a host's own two-phase button; write a new one and the arming contract (#106) becomes that host's discipline again, which is how #106 happened. And a component that reads the live health snapshot inherits `HealthAwareComponent` rather than subscribing itself: `HealthPill` and, on first run only, `ModelPullChip`. That chip is a sibling of the pill rather than markup inside `AppHeader` precisely so the header holds no health subscription for the rest of the install's life once first run ends.

`--color-danger` is reserved for the destructive and the data-integrity states, Delete and orphaned Provenance (#86), and nothing else wears it. Not the error page — the ASP.NET template's `text-danger` was a class no stylesheet here has ever defined, and `--color-danger` is not the fix — and not the health pill's dot, which has its own hues for the states it reports.

First run is a state of the same chassis, not a screen of its own (#90), and every region reads one flag rather than asking the database itself: `MainLayout` owns it and cascades it by name (`MainLayout.FirstRunCascade`). What it carries is `bool?`, and the null is load-bearing in three separate ways. It is `[PersistentState]` because without it the interactive instance starts at the default, renders once before its own query resolves, and flashes the populated chassis over the prerendered onboarding body on every first-run load — the one thing #90 is about. It is left *unset* rather than false when the probe throws, so a prerender pass that could not reach Postgres is retried by the circuit pass instead of inheriting a failure. And each consumer reads the unknown state differently on purpose: the header treats null as a third state and fetches nothing, because its pipeline is five Postgres queries and asking for them before knowing whether anything will render them is the waste that shape exists to avoid; the sidebar reads null as "not first run", because the group it would replace is what it renders in every other state anyway. The watch on the Episode feed is a one-way latch — first run is "no non-Global Project exists" and a Project is only ever created — so it is subscribed only while first run shows, un-debounced (the very first Event is normally the one that ends it, and delaying that is delaying the point), and unsubscribed for good the moment it ends. An Event landing mid-query schedules exactly one follow-up rather than racing a second query or dropping it. `MainLayoutTests` and `AppHeaderTests` pin the branches; the prerender and persistence halves are out of a renderer's reach and stay here.

Five patterns recur in every live surface, and none of them can be pinned by rendering — a render test cannot interleave two queries, and the whole point of each is what happens when they overlap. That is why the ~15 blocks the #126 inventory marked `bUnit render test` across these five were reclassified doc-only and landed here instead (#129 decision 2). **Generation guards:** any handler that awaits a query takes `var generation = ++_generation` first and drops its result if the field has moved, because the feed, a keystroke and a row click all fire into the same method and cancelling an elapsed debounce is a no-op, so overlapping queries are the ordinary case rather than the exotic one. `AppHeader` takes its generation *after* the first-run check, so a refresh discarded for arriving too early cannot invalidate a real one in flight. **Debounce lanes:** a feed-driven lane takes `Debouncer.DefaultCeilingMultiple`, a search-driven one takes none — a ceiling firing mid-word queries half a term, which is the thing the debounce exists to prevent — so a surface with both (`EpisodeList`, `WisdomSurface`, `InjectionLogTab`) holds two instances rather than sharing one. **Detail-invariant refreshes:** a keystroke or a chip narrows the list beside the detail and nothing else, so those call the refresh with `reloadDetail: false` and leave the detail field *alone* rather than assigning null — the aside's recall figures are the most expensive read on the Wisdom surface, and a list-only refresh that raced the first load would otherwise win the generation check and blank a detail still on its way. A fifth, same family: **answered-versus-in-flight.** "No detail" is two different states — the query has not come back yet, and it came back with nothing — and a surface that cannot tell them apart flashes its "this record was deleted" note on every click. `EpisodeSurface` keeps a `_loadedId` beside the detail for exactly that, and `EpisodeSurface` alone: the Wisdom surface renders its dead-link note from `SelectedId` and lives with the flash. Like the guards above, the window is unreachable from a render test — the flash is a few milliseconds long — so it is defense in depth rather than a pinned mechanism. **Failure state is a (subject, text) pair:** an action confirmed on the record on screen can fail after the curator has clicked another row, and a bare string would render "this Wisdom is untouched" under the row it is not about.

Every link a surface writes carries the Project whose universe is being *browsed*, never the record's own scope or origin. A Global-scoped Wisdom read from `mimir`'s list belongs to `mimir`'s list, and following it must not silently switch the curator to Global's; the same goes for the Injection detail's Wisdom links, and for the drill-down's produced-Wisdom links. That is why `WisdomRoute.Detail` takes the Project as a parameter rather than reading `Wisdom.ScopeProjectId`, and why `EpisodeDrillDown` takes a `ProjectId` parameter at all. `WisdomSurfaceTests.ALinkToAGlobalRow_StaysInTheBrowsedProjectsUniverse` pins the family at one site.

A drill-down is a route on its surface's own page, not a page of its own: `WisdomPage` and `EpisodePage` each carry both `@page` directives, and the literal segment outranks `ProjectPage`'s `{Tab}` parameter, so the surface component survives the click and the list beside it is neither torn down nor re-queried. That is also why a surface's `OnParametersSetAsync` runs on every selection, so anything expensive there needs a key saying what is actually on screen — and `EpisodeList`'s is `(ProjectId, IsGlobal)` rather than the id alone, because the page resolves the Project asynchronously and renders once with the incoming id beside the outgoing Project's flag.

The native Popover API's CSS has two traps, both hit in #89's review round on `HealthPill.razor.css`. First: `display` set on a `[popover]` element's own base rule is author-origin, and author-origin always beats the UA stylesheet's `[popover]:not(:popover-open) { display: none }` regardless of specificity, so the popover paints on every page load unless `display` is gated behind a `:popover-open` rule instead of sitting on the base one. Second: `:popover-open` matches only the popover element itself, never its `popovertarget` invoker button, so `.some-button:popover-open` never matches. Style the invoker's open state with `.some-button:has(+ .the-popover:popover-open)`; there is no `:has-popover-open` pseudo-class in the spec.

Two global stylesheets ship, in `App.razor`'s link order. `wwwroot/nocturne/styles.css` is the Nocturne design system vendored verbatim, minus exactly the Google Fonts `@import`, whose woff2s are inlined instead (ADR-0001; `OfflineAssetsTests` scans for a remote `url(`/`@import` and fails on one, over both roads CSS takes to a browser here — `wwwroot`, and the `Components/**/*.razor.css` that reach it as the `Mimir.Server.styles.css` bundle). Edit it and the next sync stops being a one-file swap, so Mimir's own rules go in `wwwroot/nocturne/mimir.css`, written on Nocturne's `var(--color-*)` / `var(--space-*)` / `var(--radius-*)` tokens rather than a fresh hex. Per-component rules stay in the component's `.razor.css`. The pre-#86 `wwwroot/app.css` is gone (#97): its `.lede` callers moved to `.page-notice` + Nocturne's `.text-muted`, and `WisdomCard` and the three components only it used — the rest of what still read it — were deleted with it. Reach for a Nocturne class (`.text-muted`, `.btn`) before writing a rule that restates one.

A rule two components share goes in that token layer, not in either of them (#119). Per-component CSS is scoped, so "shared" there can only mean copied, and the §8 surface chassis — the detail frame, the aside, the list head's chips — had reached three copies and drifted in three places before anyone noticed. A wrapper component (`<SurfaceAside>`) was the live alternative and lost: `::deep` in a wrapper's stylesheet does style slotted `ChildContent`, but that makes `::deep` load-bearing in a new place where hoisting instead removed it from the repo entirely — `SurfaceChassisTests` now pins zero occurrences of it, alongside every hoisted selector being defined in `mimir.css`, no scoped rule *styling* one of the chassis's classes outside a three-entry licence that names the declarations each is for, and no collision between the chassis's generic names (`.chip`, `.chips`, `.aside-note`) and the vendored `styles.css` a Nocturne sync replaces wholesale. What it reads is each rule's subject — the rightmost compound — so `.chip:hover`, `button.chip` and a one-line `@media` are caught while `InjectionDetail`'s `.pane-detail-footer p` is not: a surface styling its *own* markup underneath a chassis class is the thing that stays legal. The chassis's vocabulary is `pane-` (`.pane-detail-frame`, `.pane-aside`, `.pane-placeholder`, `.pane-danger`); `detail-` is the *contents* of a detail and stays that component's own, which is why `WisdomSurface` keeps `.detail-head`/`.detail-kind`/`.detail-editor` but renamed its frame and aside. When a surface genuinely differs, what decides where the difference lives is its children: a variant whose children are shared becomes a modifier in the token layer (`.aside-rows.is-prose`), and one whose children are that surface's own stays scoped beside them (the Injection log's `.aside-link` grid, which exists to place `.aside-link-text` and `.aside-link-count`). Splitting a layout from the children it lays out is the thing to avoid. No ordering trick is needed either way — the scoped bundle is linked last and every scoped rule carries an extra attribute selector, so it wins.
