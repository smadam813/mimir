# The Wisdom browser lists the Ambient Candidate Universe, not the selected Project's rows

Selecting a Project in the sidebar lists the **Ambient Candidate Universe** — that Project's Wisdom *plus* Global — rather than the rows whose Scope is that Project. `WisdomQuery`'s scope filter (any / Global-only / Project-scoped-only) is removed rather than rewired: the sidebar selection now names a universe, and there is nothing left for a second control to narrow. The sidebar's own per-Project counts stay Project-owned, so they still partition. Decided while specifying the `Mimir Mono` design port ([#86](https://github.com/smadam813/mimir/issues/86)).

**The question this settles**: the Wisdom browser has two defensible readings, and the design that prompted the port asserted both at once. Its list header reads `184 · mimir` — a Project-owned count — while the rows beneath it carry Scope labels reading `Global`, `mimir` and `atlas-ingest`. Those cannot both be true of one list: 184 rows cannot contain the 312 Global ones. One of the two is sample data being loose, and which one is loose decides what the central list of the whole application *means*.

**Ambient wins because it is the question a curator is actually asking.** §3 already names this set: the Ambient Candidate Universe is "the session's Project plus Global, non-Retired, minus the native-content exclusion" — the set the Brief and the Prompt lane draw from. A curator standing in `mimir` wants to know what a session in `mimir` will be told. Under the Project-scoped reading they see a set no lane ever reads, and must hold two lists in their head to answer the only question the screen is for. Ambient also earns the per-row Scope label its keep: in a single-Scope list every row says the same word, and the label is furniture.

**The cost is that the sidebar's numbers stop matching the list's length**, and that is genuinely confusing the first time. `mimir · 184` sits beside a list of 496 rows. Two things make it survivable: the counts partition, so they still add up to the tier and still answer "where is memory accumulating"; and the list header states both figures rather than one, so the arithmetic is on the screen instead of left as an inference. The alternative — counts that match the list — would make every Project's number include the same 312 Global rows, so the sidebar would tell a curator that five Projects hold 312, 496, 373, 335 and 321 Wisdom when the tier holds 589. Overlapping counts in a sidebar are worse than a stated discrepancy.

**Global's own row is the one place the two readings coincide.** Selecting Global lists Global-scoped Wisdom, because Global's ambient universe is itself. Nothing special is coded for this; it falls out of the universe definition.

**Considered options**:

- **Strictly Project-scoped, keep the scope filter** — today's behaviour, and the smallest change. Preserves all of the existing filtering power and makes count and list agree. Rejected because it leaves the browser answering a question no Recall lane asks, and because it keeps a six-control filter bar on a screen the design deliberately reduced to chips and a sidebar.
- **Strictly Project-scoped, drop the scope filter** — self-consistent and simple, with Global reached by clicking Global. Rejected on the same ground as the above, and because it makes the drawn per-row Scope label meaningless.
- **Ambient list, ambient counts** — the fully consistent version of this decision. Rejected for the overlapping-counts failure described above.
- **A scope control retained as a third chip row** — satisfies everyone, at the price of a control the design deliberately does not draw, on a screen already carrying Kind chips, a sidebar group, a tab strip and a search box. Rejected as the option that resolves the disagreement by refusing to make the decision.

**What is lost, plainly**: there is no longer any way to ask for "Project-scoped Wisdom only". A curator who wants `mimir`'s own rows without Global must read the Scope labels. That capability existed and is being deliberately removed, on the reasoning that nothing in the pipeline draws that set either — the Merge Gate promotes a Project-scoped Wisdom to Global when it recurs elsewhere, and Adjudication's Scope-split writes explicit Scopes, but neither reads "this Project excluding Global" as a set. If a real need for it appears, the correcting move is a Scope chip alongside the Kind chips, not the return of the old filter bar.

**Consequence for the Candidate Universe rule**: §3 says the universe restricts the search itself, never a ranked result after the fact, and that Storage owns each universe as its own entry point. The browser is a §8 surface rather than a Recall lane, so it does not share the lanes' entry point — but it must not assemble the universe inline either. The listing reaches the ambient set the same way a lane does: by naming it.
